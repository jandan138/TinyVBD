line search：牛顿步为什么要「试探着走」

3.3 给了每个顶点的 raw Newton 候选 $\mathbf p=\mathbf H_i^{-1}\mathbf f_i$。它有两道独立风险：$\mathbf H_i$ 不定时，$\mathbf p$ 甚至可能不是下降方向；方向正确时，full step $\alpha=1$ 仍可能冲过头、落到更高能量。line search（线搜索）处理第二道风险：沿下降方向先试探再决定走多远。把方向修正和步长接受分开，是从「解出线性系统」到「得到下降更新」之间必须补上的一课。

Newton 给候选，line search 选落点

先把 3.3 那步 Newton 看仔细。$\Delta\mathbf x_i=\mathbf H_i^{-1}\mathbf f_i$ 是怎么来的？它用当前点附近的一个二次模型近似真实能量 $G$；当 $\mathbf H_i$ 为 SPD 时，这个候选指向二次模型的碗底。问题在于：

  • 真实的 $G$ 不是二次的（弹簧能量 $\tfrac12k(l-l_0)^2$ 里 $l=\lVert\mathbf d\rVert$ 对位置是非线性的）。二次模型只在当前点附近像 $G$，离得远了就不准。
  • 牛顿一步 $\Delta\mathbf x_i$ 可能迈得很大，大到跳出了「二次模型还像 $G$」的范围。落点处真实的 $G$，完全可能比出发点还高。

所以先把 $\mathbf p=\Delta\mathbf x_i$ 当成一个候选方向：确认 $\nabla G_i^\top\mathbf p<0$ 后，真正更新的是 $\mathbf x_i\leftarrow\mathbf x_i+\alpha\,\mathbf p$，其中 $\alpha\in(0,1]$ 是待定步长。「一步走满」就是 $\alpha=1$（full step），但它只是一个候选。决定 $\alpha$ 该取多少的机制，就是 line search。

从 GAMES103 看 你写隐式积分时多半已经踩过这个坑

GAMES103 写隐式积分 + Newton 迭代时，你可能遇到过「某些帧 Newton 不收敛、能量乱跳甚至炸」。一个常见原因是没做 line search、直接 $\alpha=1$ 走满；若 Hessian 不定，还要先修方向。课上常把这些统称为「加个 line search」——这一节把方向修正与步长接受拆开。它们是优化式仿真器（Part 6 会把这个统一骨架点明）里和「组装、求解」并列的一等公民。

一步走满会怎样：冲过头，能量反升

用一个最干净的一维画面看清楚。设当前点 $x_k$，下降方向 $\mathbf p$ 指向二次模型的碗底。如果真实能量曲线在那个方向上「比二次模型更早回升」（非二次、不对称），那么走满 $\alpha=1$ 就会越过真正的谷底、爬上对面的坡——落点能量比出发点还高。对要求单调的最小化算法，这个候选不能接受；若仍写回，迭代可能开始震荡甚至发散。

line search 的对策朴素得让人安心——backtracking（回溯）：从最贪心的 $\alpha=1$ 试起，如果落点能量没下降，就把 $\alpha$ 减半（$1\to\tfrac12\to\tfrac14\to\cdots$），一直试到找出一个让能量真正下降的步长为止。因为方向 $\mathbf p$ 只要是下降方向（沿它走一小步能量必降，这点下面会讲），足够小的 $\alpha$ 就一定能下降——所以回溯总会停下来，且停在一个安全的步长上。

interactivefull step 冲过头，line search 回退把它救回来
能量曲线 + Newton 候选。候选为下降方向时，full step（α=1，红/琥珀）仍可能冲过头；line search 从 α=1 起减半，直到找到真正下降的 α（青）。若方向本身上坡，则要先修 Hessian，不能只靠缩步长。

怎么算「真正下降」：Armijo 判据

「让能量下降」其实还能再精确一点。如果只要求 $G(x_k+\alpha\mathbf p)<G(x_k)$（落点比出发点低一丁点就行），可能会接受一些「下降得微不足道」的步长，收敛拖沓。实践里用的是一个更稳的判据——Armijo condition（充分下降条件）：要求落点的下降量，至少达到「沿这个方向、按当前坡度预期下降量」的一个固定比例 $c$（通常 $c$ 取一个很小的数，如 $10^{-4}$）：

$$G(\mathbf x_k+\alpha\,\mathbf p)\ \le\ G(\mathbf x_k)\;+\;c\,\alpha\,\nabla G(\mathbf x_k)^\top\mathbf p.$$

别被式子吓到，读它的直觉就够：右边 $\nabla G^\top\mathbf p$ 是「沿 $\mathbf p$ 方向的坡度」（下降方向时它是负的），$c\,\alpha$ 倍是「我至少要兑现这么多下降」。这条件说的是：这一步的实际下降，不能比「按坡度该有的下降」小太多——既挡住「冲过头反升」，也挡住「下降太敷衍」。在 $G$ 光滑且 $\mathbf p$ 为下降方向等常规前提下，backtracking 对足够小的 $\alpha$ 会满足 Armijo，因此每个被接受的步都降低能量。整条能量序列由此单调；要进一步证明迭代点收敛到驻点，仍需梯度控制、紧性等标准假设。

为什么这件事在我们书里值得单独一节

line search 是优化式仿真的通用基础设施。3.6 会对照完整 VBD 与 TinyVBD 精简实现，12.5 则讲 IPC 的接触感知版本（还要用 CCD 限制可行步长）。补上「full step 为什么可能上升、line search 具体验收什么」，再读 12.5 就能把下降验收和不穿透约束分开。（这一节的组织受 Minchen Li《Physics-Based Simulation》把 line search 当优化积分器一等公民的讲法启发；延伸阅读见 a-3 参考文献。）

步长 vs 方向：line search 救不了的那种翻车

这里要钉死一个容易混的边界——line search 只管「走多远」，不管「方向对不对」。回想 1.5 那个「碗 vs 马鞍」：

  • 如果局部 Hessian $\mathbf H_i$ 正定（碗），那么牛顿方向 $\mathbf p=\mathbf H_i^{-1}\mathbf f_i$ 一定是下降方向——沿它走一小步能量必降。这种情况 line search 总能找到好步长，它专治「方向对、但一步走太猛」。
  • 但如果 $\mathbf H_i$ 不定（马鞍，比如压缩弹簧 $\lambda_\perp<0$），牛顿方向可能本身就指向上坡。这时无论 $\alpha$ 缩到多小，沿这个方向走都是在爬坡——line search 把步长缩到零也救不回来。

所以「方向问题」要用 modified Hessian、PSD projection、damping 或 trust region 等手段处理（见 1.5 与 10.2），让 $\mathbf p$ 成为下降方向；line search 再在这个方向上挑安全步长。分工不变：谱/模型修正保方向，line search 保步长。若原 Hessian 已经 SPD，当然不必重复投影；若方向本来上坡，单独缩步长也救不回来。Part 14 还会用 eigenbasis 和 determinant 反例把这条边界展开。

从 TinyVBD 看 完整算法与精简 C++ 选择不同

论文/完整 VBD 可以只重算顶点邻域的 $G_i$，对每个 block 候选做便宜的 local backtracking；一旦 Armijo 或至少 $\Delta G_i\le0$ 通过，3.2 的 $\Delta G=\Delta G_i$ 就把它提升为全局下降。TinyVBD 的 main.cpp 为简洁关闭了这一步：h.colPivHouseholderQr().solve(f) 后直接以 $\alpha=1$ 写回，并且没有 PSD 修正或显式 det guard。QR 只是在解线性系统，不是下降证明。

另一个容易倒灌的实现细节是 Newton/Warp 路径里的 abs(det(H)) > 1e-8。那是另一套实现在显式求逆前使用的尺度相关可逆性 heuristic，不存在于 TinyVBD C++，也不能替代 PSD 或 line search：不定矩阵的 determinant 完全可能很大。故 TinyVBD 这份代码应被理解为精简、经验性 full-step 实现，而不能继承带下降接受条件的单调定理。

这一节你要带走的

三句话：(1) $\mathbf H^{-1}\mathbf f$ 只是候选：$\mathbf H$ 不定会给上坡方向，方向正确时 $\alpha=1$ 仍可能冲过头；(2) modified Hessian/PSD/damping 负责构造下降方向，backtracking + Armijo 负责只接受充分下降的步长，二者职责不同；(3) 完整 VBD 可做局部 backtracking，而 TinyVBD C++ 直接走 QR full step、没有 line search/PSD/det guard，Newton/Warp 的 determinant heuristic 也不能倒灌成它的保证。
