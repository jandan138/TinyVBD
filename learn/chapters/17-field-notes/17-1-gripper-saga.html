实战复盘：一条专家轨迹的跨后端复刻战役

Part 15–16 讲的是「教科书版」的夹爪联合求解。这一页是它在真实项目里的出处：我在 EmbodiedEval OS 的 TaskBook-03B P7 系列里，把一条 Isaac 成功的专家轨迹复刻到 Newton 的完整战役。所有数字都出自工程记录（文中标注文件名），包括没有闭合的部分。

3 分钟电梯版（面试可直接讲）

我做的难题是跨后端物理复刻：把一条在 Isaac 里成功「夹苹果入碗」的专家轨迹（425 行动作），在 Newton 上用真接触 + 摩擦重放——不允许用球铰把苹果粘在手上。

第一层困难不是物理，是数据合同：最初 425 行全部执行却零接触，根因是 reset 时苹果和碗被镜像了 y 而机器人没有，两者相距 0.723 m。我把 reset 绑定、动作映射、模型状态拆成三份独立合同修复。

第二层困难是精确定位：接触有了，但「碰到」变不成「捏住」。我用 Isaac/Newton 双端探针加 fail-closed 比较器，把分歧锁定在动作第 166 行：同样的指令目标，Isaac 双侧夹爪力激活 [true, true]，Newton 是 [true, false]——分歧发生在接触响应里，不在命令里。

第三层是结构修复：我把碰撞表示从原始三角网格换成源等价凸件、把「主动 drive + 被动 mimic」拓扑投影进求解器，苹果抬升 0.162 m、无支撑携带 57 行、成功入碗；零摩擦对照只有 0.005 m——因果闭环。

但资格没有闭合：换成 5 次冷启动资格队列，0/5——Newton 能抬能运，但保持不住持握完成放置。我把求解结构升级为「mimic、有界 drive、接触在同一外迭代里联合求解」，第一个 substep 闭合到亚微米（$5.9\times10^{-8}$ m），第二个 substep 仍不收敛。这期间还解决了两个隐藏难题：跨冷进程的惯量不确定性（并行归约顺序漂移）和一次伪装成物理崩溃的结果信封溢出。

这个故事的价值不在「成功了」，在于每一步都有证据边界：我知道问题收敛到了哪一层。

背景：跨后端复刻在评什么

EmbodiedEval OS 是一个评测操作系统：同一条任务，换物理后端、换模型、换场景，产出有证据支撑的成败声明。TaskBook-03B P7 系列的任务，是把 EBench Lift2 apple_to_fruit_bowl 一条 Isaac 成功的专家轨迹迁移到 Newton 重放：源动作流 425 行（arm_action [425,12]、gripper_action [425,4]、base_motion [425,3]），节拍 1/30 s（2026-07-26-taskbook03b-p7-reference-source-and-action-audit.md）。

关键纪律叫 friction_only：不允许 robot–apple 约束、不允许物体传送、reset 后零苹果写入。这条纪律是被历史教训逼出来的——更早的 R4/R8 结果其实是「接触触发后挂球铰」的约束辅助搬运，看起来苹果入碗了，机制却是假的，后来被改标 constraint_assisted_transport（2026-07-28-taskbook03b-p7-4f-frictional-grasp-fidelity.md）。评测的第一课：先定义什么不算成功，再定义什么算。

第一幕：425 行跑完，苹果留在桌上

friction_only 基线的结果很冷：最大抬升 0.0006456 m，无支撑携带 0 行，双侧力激活只在 169–195 行出现过 27 行；终态 apple-in-bowl 为 false。零摩擦对照抬升 0.0006778 m——摩擦开不开，结果几乎一样，说明摩擦压根没机会起作用（同 P7-4F 记录）。

动作通路是干净的：425/425 行执行、1710 次 endpoint 交换、动作重构误差 $10^{-13}$ 量级。也就是说，命令全部送达，物理没有响应。这就是 Part 15.1 说的两层成功：动作通路全绿，抓取物理全红。

第二幕：把分歧钉在第 166 行

「夹不住」是个终态描述，没法直接修。我做的是造了一台「比较机器」：Isaac 侧精确探针、Newton 侧 opt-in 诊断、fail-closed 比较器，对齐规则钉死为「动作第 $i$ 行 ↔ Isaac post frame $i+1$ ↔ Newton post row $i$」（2026-07-28-taskbook03b-p7-4g-contact-to-hold-divergence.md）。

结果：最后一个一致行是 165，首个分歧行是 166。这一行上，两侧的指令目标完全相同（均为 [0.0, 0.0]），但测量态分道扬镳：jaw 力激活 Isaac [true, true] vs Newton [true, false]，jaw 面间距差 6.3 mm。记录里的原句值得背下来："The split happens in embodiment/contact response, not in the frozen command row." 同样的命令，不同的接触响应——嫌疑第一次从「数据」转向「求解结构」。

按合同梯子（15.5）排序，两个优先候选：碰撞表示（Isaac 用 convexHull/凸分解，Newton 当时导入原始 MESH）和驱动拓扑（Isaac 是 fr_joint7 主动 drive stiffness 1000 / damping 100 + fr_joint8 被动 mimic，gearing $-1$；Newton 是双侧独立 PD，无 mimic）。注意它们当时的身份：优先候选，不是已证根因。

第三幕：最小物理修复，首次闭合

P7-4Q 做了四个 provider/task-local 的最小修复：两条右 jaw 换成源等价凸包；苹果用保留的 PhysX-cooked 凸分解件；源「主动 drive + 被动 mimic」拓扑用 XPBD shared-parent prismatic mimic 投影表示；接触摩擦算子接受实际凸件数（2026-07-29-taskbook03b-p7-4q-frictional-grasp-visual-closure.md）。

同一条冻结的 425 行轨迹上：苹果抬升 0.162356 m、无支撑携带 57 行、双侧力激活分数 1.00、终态入碗 true；零摩擦对照 0.005060 m、0 行、0.00、false。32 倍的抬升差加上负对照，构成单轨迹上的摩擦因果闭环——这正是 16.5 那个 lab 在真实世界的原型。

但我在记录里给自己留了一句警告，现在也留在这页上："The accepted result is one run, not a repeatability claim." 单次成功不是可重复性声明。这个克制很快就被证明是必要的。

第四幕：资格队列不闭合，以及求解结构的硬仗

P7-10 把单次成功升级为资格测试：5 个独立 GPU 冷启动。结果 0/5——但失败方式变了：每次都出现真摩擦抬升（最大 0.150–0.152 m）和无支撑携带，却无一次完成放置。记录原句："Newton can make force-active bilateral contact, lift, and carry. It does not retain the Isaac-success hold state closely enough to complete placement." 从「夹不住」到「保持不住」，问题被压缩到了运输段的 contact-to-hold 漂移。

求解器级归因用 128 迭代台账说话：hard mimic 每迭代最多移除 10.308 μm 的右 q 跨度，而 mimic 缩减接触只能恢复 0.436 μm、源 drive 只改 0.093 μm——硬 mimic 投影在每轮迭代里反复改写接触刚建立的解，这正是 15.4 动画的真实量化版。三个预申报的保守修复候选（改顺序、减位置 mimic、只留速度 mimic）全部被数据拒绝后，我在 P7-12 记录里写下决策："Continuing with another coefficient or solver-order edit would be tuning from a correlated trace." 不再从相关轨迹上调参，转向结构修复。

结构修复是 P7-11 的耦合 profile newton_xpbd_128_coupled_passive_mimic_drive_contact_v1：每个 XPBD 外迭代在同一共享广义状态上依次解 passive mimic → bounded drive → normal contact → friction。这场仗打得很难看：R5 广义增量一度炸到 $1.14\times10^{19}$（mimic 公式重复相减）；R11 数值上跑完了 128 迭代，右 jaw 却冲到 0.1475 m（冻结上限 0.044 m）——记录原句："This is numerical completion, not physical qualification." 数值跑完不等于物理合格。最终 R128 把第一个 substep 闭合到亚微米：最大关节位置写误差 $5.86\times10^{-8}$ m、速度写误差 $4.15\times10^{-7}$ m/s。但第二个物理 substep 的首次耦合外求解仍不收敛，正式行 166 三冷启动资格 0/3，P7-12 因果诊断定格在 inconclusive。

与此同时，代码里存在一条平行路线：一个版本锁定的 Kamino 兼容层（newton_kamino_mimic_solver.py），把两条 mimic 行作为双侧约束注入 Kamino 的 dense PADMM 求解——mimic 和 contact 进了同一次求解；但源 drive 的力限在 Kamino 车道仍是 authored_but_not_enforced（写了但求解器不执行）。16.3 说的「更近的底座，不是写完的答案」，就是这里。

卫星故事：同一战役里的另外四场仗

主线之外，这四个独立难题同样塑造了最终结果。每个都能单独讲一轮面试。

坐标合同：425 行零接触的真相

更早的 R2 曾「跑完 425 行但零接触」。排查发现：抓取段源行 166 处，源苹果在 $y=-0.391$，而 Newton 重放的苹果在 $y=+0.391$——苹果和碗被镜像了，机器人没有，两者相距 0.723 m，全程最近也有 0.274 m。零接触不是策略错、不是关节顺序错、不是渲染错。修复是把 reset 世界绑定、动作控制映射、模型状态映射拆成三份独立合同，y 反射恰好出现一次（2026-07-26-taskbook03b-p7r3-coordinate-contract-review.md）。先怀疑数据合同，再怀疑求解器——这条顺序后来写进了整个项目的排查纪律。

冷启动数值确定性：物理哈希从第 0 行就不同

资格队列需要「同输入必同输出」，但两个冷进程从第 0 行起 physics_state_sha256 就不同。逐域冻结对比后只剩一个差异：Lift2 刚体没给对角惯量，Newton 用并行 Warp 原子归约从三角网格算惯量，归约顺序跨进程漂移，body_inv_inertia 最大差 0.3188。修复：仅对 Lift2 改用固定 host 顺序的实体三角形积分 + float64 累加，两个独立冷进程 200/200 substep 零散布（2026-08-06-taskbook03b-p7-10-frictional-transfer-qualification.md）。随后 P7-14 升级 Warp 1.15 的 DeterministicMode.RUN_TO_RUN，3/3 独立冷启动位精确一致。期间还有一个证据合同教训：Newton 的原始接触候选数会漂移，但它只是几何清单，不证明约束行被选中或产生了力——于是把它从门控证据降级为诊断（2026-08-09-taskbook03b-p7-14-row166-cold-start-reproducibility.md）。

row-83 信封溢出：一次伪装成物理崩溃的协议失败

P7-12 队列的 worker 在第 83 行后以退出码 66 消失，看起来像物理崩了。我没有动一行物理代码，先做只读取证：worker 结果行上限 1 MiB，而上一个被接受的结果已达 929,992 字节（其中 gripper_mimic_coupling 独占 842,712 字节）——最佳解释是结果信封溢出，而不是 Newton 出了新物理缺陷。修复也只动协议：无界迭代历史换成确定性内联摘要，完整载荷走哈希绑定的 artifact 发布。之后 canary 跨越 row-83，row-166 提交 609,539 字节结果 + 7.5 MB 诊断 artifact，worker 返回码 0（2026-08-08-taskbook03b-p7-13-row83-result-envelope-overflow-repair.md）。取证先于改代码：崩溃现场的样子经常说谎。

渲染污染物理：1209 → 1209 的修复

物理闭合后要做视频证据，但物理 jaw 是 CONVEX_MESH，光线追踪器不显示。第一个方案（r53）给渲染加两个克隆 mesh——被我自己拒了：它改变了模型 shape 数，扰动物理。接受的方案是给 SensorTiledCamera 单独的 renderer-only shape-type 数组，只把两个 shape ID 暴露为 MESH，模型 shape 数 1209 → 1209 不变；最终视频是对 425 个留存状态逐个验哈希后的零步后渲染（同 P7-4Q 记录）。渲染是观众，不是演员——它不许碰物理的状态空间。

边界：现在确切知道什么

到 P7-14 为止，这页里每个声明的状态：

  • 已闭合：单轨迹摩擦因果（P7-4Q，含零摩擦对照）；reset 确定性（200/200 零散布）；冷启动可复现性（3/3 位精确）；row-83 溢出（协议级修复并跨越）。
  • 未闭合：行 166 资格 0/3；耦合求解第二 substep 不收敛；P7-12 因果诊断 inconclusive（P7-14 通过后已授权重启该队列）；Kamino 车道缺有界 drive 的求解内执行。
  • 从未声明：这页所有内容 model-free、score-free，不声称 Newton 与 Isaac 物理等价，不声称任何模型分数。

面试里我最想传达的就是这张表：「成功一次」与「资格通过」之间隔着可复现性工程，而我知道这条缝具体在哪、多宽。

追问预案

面试官大概率会沿着这几条线深挖，每条我都有记录背书：

  • 「为什么不直接调大摩擦系数？」——三个预申报调参候选全部被数据拒绝；再拧系数就是 tuning from a correlated trace（P7-12）。
  • 「怎么证明分歧在物理而不是动作/渲染？」——双端探针 + fail-closed 比较器；行 166 两侧命令逐字节一致，测量态分叉（P7-4G）。
  • 「你最大的一次误判？」——早期结果其实是球铰搬运，被摩擦抓取的目标误导；由此立了 friction_only 纪律和零摩擦负对照（P7-4F）。
  • 「联合求解到底做到哪一步？」——mimic + contact 已进 Kamino 同一 dense PADMM；XPBD 耦合首 substep 闭合到 $5.9\times10^{-8}$ m；bounded drive 与第二 substep 未闭合（P7-11、Kamino 模块头）。
  • 「GPU 确定性怎么搞定的？」——先修 reset 惯量的并行归约（host 固定顺序 + float64），再用 Warp RUN_TO_RUN 锁冷启动（P7-10 / P7-14）。
  • 「失败最惨的一次？」——R5 广义增量 $1.14\times10^{19}$，公式重复相减；教训是每次只改一个变量并冻结其余（P7-11）。
  • 「重做一次会改什么？」——把确定性验证提到物理排查之前：没有 3/3 位精确之前，一切跨进程力对比都在比噪声。
