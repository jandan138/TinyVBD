skip spring = 弯曲，与迭代数的影响

这一节调两个旋钮。一个是 skip spring——一根连 i 与 i+2 的弹簧，改变问题本身、给软趴趴的链一点抗弯刚度；另一个是 numIterations——不改目标 $G$，但改变有限预算下的求解误差。迭代正常收敛时，多做 sweep 通常更接近该 substep 的离散解，却不是逐次靠近的无条件保证。

纯距离弹簧的链没有弯曲刚度

一条只有相邻距离弹簧（i 连 i+1）的链，有一个你可能没注意到的问题：它完全不抵抗弯折。每根距离弹簧只在乎两端的长度，对「链拐了个弯」没有任何意见。于是这种链在重力下会瘫成一团、卷曲、自己折叠——因为把它对折，所有距离弹簧的长度都没变，能量一点没涨，求解器没有任何力去把它撑开。一根真实的头发或绳子不会这样，它有弯曲刚度（bending stiffness）。

从 GAMES103 看 你大概加过 bending 约束

课上做布料 / 绳子时，你多半在相邻距离弹簧之外，额外加过一层「弯曲约束」——比如连接隔一个的顶点，或约束二面角。没有它，布会软成一摊。skip spring 就是这套思路里最便宜的一种弯曲能量：不算二面角，只多加一根跨一个顶点的距离弹簧。

skip spring：连 i 与 i+2 的一根便宜弹簧

看 Strand.h 里带 skip spring 的那个 from(...)。在为每条相邻边（i, i+1）建好弹簧后，只要 addSkipSpring 为真，它就顺手再建一根 (i, i+2) 的弹簧：

Strand.h · from()
vertAdjacentEdges[i].push_back(edgeId);
vertAdjacentEdges[i+1].push_back(edgeId);
edgesStiffness.push_back(stiffness);
lengthesNew.push_back(lengthes[i]);
if (addSkipSpring && i < lengthes.size() - 1)
{
    edgeId = edges.size();
    edge << i, i + 2;                          // 跨过 i+1，连 i 和 i+2
    edges.push_back(edge);
    vertAdjacentEdges[i].push_back(edgeId);
    vertAdjacentEdges[i + 2].push_back(edgeId);
    edgesStiffness.push_back(stiffnessSkipSpring);  // 默认 100，比主弹簧软得多
    lengthesNew.push_back(lengthes[i] + lengthes[i+1]); // rest = 两段之和
}

三个细节值得品：(1) 这根弹簧用单独的 stiffnessSkipSpring（默认 100），通常远比主距离弹簧软；(2) 它的 rest length 取 lengthes[i] + lengthes[i+1]，也就是两段直接相加——意味着「链是直的」时它恰好等于 rest、不出力；(3) 一旦链在 i+1 处弯折，i 到 i+2 的直线距离就变短，这根弹簧被压缩、产生一个把链撑直的恢复力。这就是它近似弯曲能量的全部机制：用「跨节点距离」间接惩罚弯折。对 VBD 的求解器而言，它不过是 vertAdjacentEdges 里多出来的一条边，solve() 照常累加它的力和 Hessian（见 4.3），不需要任何特殊处理。

这就是 initializeTilted() 里 skipSpringStrength = 100 的来历

默认实验 5.1 打开了 skip spring，正是为了让那根吊重锤的链看起来像根有筋骨的绳，而不是一摊会自折叠的距离弹簧。initializeStiffRatio() 同样开了它。

手算一遍：直的时候力为 0，折 90° 时回复力多大

上面说「链直时 skip spring 不出力、链弯时它产生撑直的回复力」，这两句都能代数字算出来。仿照 4.3/12-7 的节奏，用本实验的真实间距 dis = 0.05，取顶点 $i,\ i{+}1,\ i{+}2$ 三点，看跨节点那根 skip spring 的当前长度 $l$ 与它的 rest length $l_0$。

情形一：链是直的。三点共线，$i$ 到 $i{+}2$ 的直线距离正好是两段相加：

$$l = \mathtt{dis} + \mathtt{dis} = 0.05 + 0.05 = 0.10 = l_0\quad\Longrightarrow\quad l - l_0 = 0$$

skip spring 的力是 $\mathbf f = k\frac{l_0-l}{l}\mathbf d$（1.5）。$l=l_0$ 时 $l_0-l=0$，力恒为 0——直链时这根弹簧完全不出力，正合源码把 rest 取成 lengthes[i]+lengthes[i+1] 的用意：直就是它的自然态。

情形二：在 $i{+}1$ 处折成直角（90°）。两段仍各长 dis，但夹角从 180° 变成 90°，$i$ 到 $i{+}2$ 的直线距离由勾股定理给出：

$$l = \sqrt{\mathtt{dis}^2 + \mathtt{dis}^2} = \mathtt{dis}\sqrt{2} = 0.05 \times 1.41421 \approx 0.07071$$
$$l_0 - l = 0.10 - 0.07071 \approx 0.02929$$

跨节点距离从 $0.10$ 缩短到约 $0.0707$——skip spring 被压缩了约 $0.029$。把压缩量乘上刚度 $k=\mathtt{stiffnessSkipSpring}=100$，看回复力的标量大小 $F = k\frac{|l_0-l|}{l}$：

$$F = k\,\frac{l_0-l}{l} = 100 \times \frac{0.02929}{0.07071} \approx 100 \times 0.4142 \approx 41.4$$

读出物理：折弯让 $l<l_0$，弹簧被压短，$l_0-l>0$，于是 $\mathbf f=k\frac{l_0-l}{l}\mathbf d$ 沿 $\mathbf d=\mathbf x_i-\mathbf x_{i+2}$ 把两端往外推——也就是把折角撑开、把链扳直。这股力越折越大（折得越狠 $l$ 越小、$l_0-l$ 越大），正是「抗弯刚度」的来源。而它只用了一根普通距离弹簧、$k$ 才 100，比主弹簧软得多——这就是 skip spring 作为「最便宜弯曲能量」的全部算术。

这组数是为讲解构造的自洽示例

$0.029$、$41.4$ 这些数都用本实验真实的 dis=0.05、stiffnessSkipSpring=100 直接代出来、可拿计算器复算；但「折 90°」是为讲解挑的一个干净角度，真实仿真里链各处折角连续变化。要记的趋势是：直链 $\to$ 力为 0；越折 $\to$ $l$ 越小 $\to$ 回复力越大、方向永远是把链扳直。具体某个力的小数会随折角和 $k$ 变，因果方向不变。

迭代数：欠收敛误差与「看起来像阻尼」

第二个旋钮是 numIterations（默认 100）。回忆主循环（4.5）：每个 substep 里，TinyVBD 把 solve() 这个 Gauss-Seidel sweep 重复 numIterations 次。设计目标是更充分地逼近增量势能 $G$ 的极小点；在给定 demo 的正常收敛区间里，多做 sweep 往往会减小求解误差，但当前 raw full step 没有验收，不能保证「每多一次都更接近」。

  • 迭代多：若迭代正在收敛，通常更接近该 substep 的离散解，链更「绷」、欠收敛误差更小；
  • 迭代少：有限预算常让结果偏软、偏迟钝，外观看起来像多了一层阻尼，但这首先是求解器欠收敛，不要和 backward Euler 本身的时间离散数值阻尼混为一谈。

这里没有「无论迭代多少都不爆」的 raw 代码铁律。无条件成立的是单 block 恒等式 $\Delta G=\Delta G_i$；只有精确 block minimizer，或先构造下降方向再经 backtracking/Armijo 验收的步，才保证已接受更新使 $G$ 不升。TinyVBD C++ 用 QR 解出候选后直接走 $\alpha=1$，没有 PSD、显式 det guard 或 line search，所以 1 次迭代也可能升能或失败。给定 demo 在低迭代下常只是变软而未爆，这是工程观察；精确 backward Euler 在线性测试方程上的 A-stability 也不能替这份有限迭代 raw 实现补出保证。

从 PBD 看 同样是「迭代越多越硬」，含义却不同

PBD 里「迭代越多越硬」是个病：有效刚度随迭代数漂移，stiffness 成了 solver 设置的产物而非物理量（2.1）。VBD 的区别是目标 $G$ 与物理刚度 $k$ 不随迭代预算改变；在求解器满足收敛条件时，增加迭代是在减小对这个固定离散目标的求解误差。有限次 raw sweep 的结果当然仍会随预算变化，而且不保证逐次靠近。

迭代 vs substeps：另一种花预算的方式

除了在一个时间步内多迭代，你还能把时间步切细：主循环开头 params.dt /= params.substeps，把一帧拆成多个 substep，每个 substep 用更小的 $h$ 跑一遍完整的 forwardStep + 迭代 + updateVelocity。更小的 $h$ 让惯性项 $m/h^2$ 的正曲率偏置更大，也让每个子步的运动更短；它通常有助于条件与时间精度，但不保证总 Hessian 凸或 raw 步下降。两种预算的含义不同：同一个 $h$ 多迭代是在近似同一个离散目标，把 $h$ 切细成多 substep则改变了时间离散与目标序列，不能说二者只是通往同一个 $\arg\min G$ 的两条等价路线。

interactive把玩 skip spring 与迭代数：弯曲怎么来、迭代怎么影响软硬
拖动链、调迭代滑块：关掉弯曲（skip spring）时链如何卷起来自折叠，开启后又如何被那根跨节点弹簧（上面算过的回复力）撑直；把迭代数压低时链如何因欠收敛而变软、看起来更黏。在这个 widget 的给定参数范围内运行通常保持有限；这不是 raw C++ 在任意刚度、步长或构形下稳不发散的证明。

这一节你要带走的

三句话：(1) skip spring 连 i 与 i+2、rest length 取两段之和、用很软的 stiffnessSkipSpring（默认 100），是一种最便宜的弯曲能量——没有它，纯距离弹簧的链会自折叠卷曲；(2) 在收敛正常的给定 demo 中，更多 iteration 往往减小欠收敛误差，低迭代则常显得偏软，但 TinyVBD 的 raw QR full step 没有「1 次也必不发散」的保证；(3) 切 substep 会改变时间离散并增强惯性偏置，不等同于在同一个 $G$ 上多迭代。下一节 5.4 给你一张完整的实验菜单，把所有旋钮和 main.cpp 的 config 对上号。
