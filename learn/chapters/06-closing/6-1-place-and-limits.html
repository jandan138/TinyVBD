VBD 在谱系里的位置、局限与 AVBD

书快读完了，是时候退后一步，把 VBD 放回它所在的谱系，看清它到底赢在哪、又输在哪。一个诚实的收尾不该只夸它好——理解它的边界，和理解它的招牌一样重要。

VBD 站在谱系的哪一格

用一句话给 VBD 定位：它是在真正的增量势能 $G(\mathbf x)$ 上做的、per-vertex 的 block coordinate descent。这一句话里每个词都来之不易，我们把它拆开，对照 2.4 的谱系图复盘一遍。

先回忆那张谱系图的主轴（2.4）：这些方法共享增量动力学 / 能量-约束视角，却不都在解同一个固定 $\min G$。原始 PBD 做位置投影，XPBD 迭代 compliant KKT，PD 受限于可投影能量；VBD 则和用于变分隐式 FEM 的 global Newton 一样，直接面对明确写出的 incremental potential。VBD 在这一层里的「怎么解」有三个同时成立的特征，正是它的坐标：

  • 对象是真正的 $G$。它直接最小化完整的增量势能 $G(\mathbf x)=\frac{1}{2h^2}\lVert\mathbf x-\mathbf y\rVert_M^2+E(\mathbf x)$，而不是某个约束违反量的近似。每个顶点的局部牛顿步用的是完整的局部 Hessian $\mathbf H_i=\frac{m_i}{h^2}\mathbf I+\sum_j \partial^2 E_j/\partial\mathbf x_i^2$，惯性项加弹性项一项不少（3.3）。
  • 更新顺序是 Gauss-Seidel，信息传播通常比 Jacobi 快。一次只动一个顶点，且立刻用上刚更新过的邻居——这是 Gauss-Seidel 而非 Jacobi，所以信息在一次 sweep 内就能往前串一截；具体收敛仍取决于曲率、接受机制和问题条件数（3.1）。
  • 并行度却接近 Jacobi。靠对顶点图做 graph coloring：同色顶点互不相邻、可并行更新，颜色数远少于 XPBD 要着色的约束/对偶图。于是 VBD 拿到了「Gauss-Seidel 顺序 + 近 Jacobi 并行」这个看似矛盾的组合（3.5）。

还有一个隐性但关键的坐标：VBD 是 primal 求解器——它直接在位置这个原始变量上下降，而不是像 XPBD 那样去解一套 dual（对偶 / 约束力 $\lambda$）系统。这一条决定了它在高质量比下的命运，下面会展开。

复盘它相对 XPBD 的几个赢面

这本书的主线是「从 PBD 到 VBD」，所以最值得对照的是 XPBD。把前面各章算过的账汇总，VBD 的赢面有四条，且都能追到它「最小化真正的 $G$ + primal + 完整 Hessian」这个根上：

  • 目标是真正的 $G$，而且能做局部验收。XPBD 本质是约束近似，且只保留惯性项那部分 Hessian（丢掉了弹性项的二阶信息）；大时间步 $h$ 或少迭代时，它会偏离真正的隐式欧拉解。VBD 保留完整局部 Hessian，并有 $\Delta G=\Delta G_i$ 这条单 block 恒等式：若 block 被精确最小化，或候选经 backtracking/Armijo 验收，已接受更新才保证全局 $G$ 不增（3.2）。TinyVBD C++ 的 raw QR full step 没做这项验收。
  • 扛得住高质量比。这是全书最戏剧化的一幕（5.1）：XPBD 是 dual 求解器，修正按逆质量分配，一根末端重 1000× 的 strand 会被「轻的拽不动重的」逼到崩溃；VBD 是 primal，直接解位置，高质量比对它没有这种结构性压力。TinyVBD 默认跑的 initializeTilted() 就是这个 1:1000 实验。
  • 不替你决定初始化。XPBD 把初始位置强制成惯性预测；VBD 不强制任何初始化，这恰恰是它能做自适应初始化的前提——自由下落的顶点带上完整重力、被托住的顶点停在原位，避免把叠放物初始化成穿插的自由下落态（4.2）。
  • 有便宜的下降验收接口，但实现必须真的使用。$\Delta G=\Delta G_i$ 让局部能量检查直接成为全局检查；惯性项 $\frac{m_i}{h^2}\mathbf I$ 也提供正曲率偏置。可负弹性曲率仍可能让总 Hessian 不定，SPD 方向修正与 line search 又分别处理方向和步长。TinyVBD C++ 不做 PSD 修正、显式 det guard 或 line search，只直接接受 QR raw full step，所以给定 demo 的鲁棒性不能写成无条件定理（3.6）。
一句话记住它的位置

VBD = 在真正的 $G$ 上做 per-vertex block 优化，用顶点图着色换来「Gauss-Seidel 顺序 + 近 Jacobi 并行」，且是 primal、保留完整局部 Hessian。结构上，任意单 block 位移都满足 $\Delta G=\Delta G_i$；算法上，只有精确 block minimizer 或经下降验收的候选才给出单调链。TinyVBD 的 raw C++ 省掉验收，是这个框架的经验性精简实现。

本章反复用四个问题给方法定位——最小化什么 · primal 还是 dual · 更新顺序 · 保留多少 Hessian（结尾还会让你「下次遇到新方法本能地问这几个」）。把散在 Part 2 与本章的判据一次性摆成一张速查表，五行就是这一族的全部坐标：

横着扫一遍就能读出全书主线：往右走，「最小化什么」从约束近似收敛到真正的 $G$；「保留多少 Hessian」从几乎不用爬到完整。VBD 同时拿到「真 $G$ + primal + Gauss-Seidel 顺序 + 着色并行」，并能用局部 $G_i$ 验收全局改变量；但验收不是 raw Newton 自动附赠的。它的主要收敛代价仍落在最后一列那个高刚度比。

把仿真器看成优化器：一帧的通用骨架

到这里可以把「物理仿真器」暂时翻译成「优化器」。只要你走的是隐式欧拉 / 增量势能这条路，稳健版本的一帧通常沿同一个骨架组织：先写出 $G(\mathbf x)$，再装配导数，构造候选方向，修正方向或模型，挑安全步长，最后验收新位置。精简实现可以省掉其中若干守卫，但也就不能继承相应保证。

optimization-based simulator skeleton
given x_n, v_n:
    y = inertial_prediction(x_n, v_n, h)
    x = initialize_guess(y)

    repeat until converged or iteration budget used:
        assemble energy G(x) = inertia(x, y) + elastic(x) + contact(x)
        assemble gradient/force and Hessian (or local Hessian blocks)
        make Hessian usable as a descent model (PSD projection, positive shift, damping, or trust region)
        solve for a direction p
        choose step length alpha (line search; contact solvers also apply CCD)
        accept x = x + alpha * p

    update velocity from x - x_n

这段伪代码故意写得像「优化器」而不是像某个具体引擎。因为 VBD、全局 Newton、IPC 都能落到它上面：

求解器装配什么怎么求方向怎么选步长 / 保证
VBD / TinyVBD每个顶点邻接的弹性 / 接触元件块per-vertex $3\times3$ 局部 Newton，Gauss-Seidel sweep完整方法可用局部 backtracking/Armijo 验收；TinyVBD C++ 则直接 QR raw full step，无 PSD、det guard 或 line search，故无逐步单调保证（3.6）
global Newton全局梯度与稀疏 Hessian解一个大稀疏线性系统稳健实现常用 PSD / damping 保方向，再用 backtracking line search 保下降（3.4）

为什么这张骨架图重要

它把后半本书的新增内容都接回同一根线：FEM 只是在 elastic(x) 里把弹簧换成 $\sum_e V_0^e\psi(F^e)$（Part 9），Newton/Warp 的 production VBD 路径在「make Hessian usable」处加 per-element 投影和阻尼（10.2），IPC 在 contact(x) 与 line search 处加 barrier 和 CCD（Part 12）。这些机制不属于 TinyVBD C++，尤其不能把 Newton/Warp 的 determinant heuristic 倒灌成 C++ 的 det guard。这套组织受《Physics-Based Simulation》把仿真统一写成优化流程的讲法启发；这里用本书自己的 VBD / Newton / IPC 例子重写。

诚实地交代它的局限

没有银弹。VBD 的强项和弱项是同一枚硬币的两面——它把目标拆成局部 block，使局部验收便宜、扫描可并行、并在高质量比 demo 中表现良好；但局部传播也带来三处真实的短板。若具体实现不做下降验收，「局部」本身并不自动等于「稳定」。

1. 信息传播慢：超硬、超高分辨率系统不理想

因为一次只动一个顶点、靠 Gauss-Seidel + 着色串联，信息每个 step 大约只能传播 ~(#colors × #iterations) 远。对一根 20 顶点的 strand 这绰绰有余；但对一个高分辨率、又非常硬的系统，要把一端的扰动传到另一端就需要很多次迭代，收敛会拖慢。这种场景里，一个直接面对全局耦合的 Newton 求解器（解整个大稀疏系统）反而可能更划算。局部方法的代价，就是它看不到「远处」。

2. 高刚度比下收敛差

这是 5.2 专门考的软肋。注意它和高质量比是两回事：高质量比 VBD 不怕，高刚度比（high stiffness ratio，比如相邻弹簧 1:10000）才是它的痛点。当系统里同时存在极软和极硬的部分，局部下降在硬的方向上步子迈不开、收敛极慢。TinyVBD 的 initializeStiffRatio()（交替刚度 1e4/1e8）就是用来亲手撞这堵墙的——你会看到它迟迟收不干净。

高质量比 vs 高刚度比：一正一反，别一锅烩

这俩「高…比」最容易记混。高质量比是 VBD 的结构强项，且在 5.1 的 1000× 重锤 demo 中表现鲁棒；高刚度比则是 VBD 的收敛软肋（5.2）。方向正好相反，但两边的具体运行结果都应按给定参数解读，不能把 demo 观察升级成 raw 实现的任意参数定理。11.1 还会专门搭一座桥再纠一遍。

3. 惩罚式碰撞不保证无穿透

完整版 VBD 用惩罚力（penalty）处理接触：穿透越深、回推力越大。这在能量框架里很自然，但惩罚力是「软」的——它把穿透当作要最小化的能量项去压，而不是一道硬约束。于是理论上不保证零穿透，尤其在大穿透或高刚度比叠加时。TinyVBD 这根 strand 干脆没有碰撞，所以这一条你在 demo 里碰不到，但在用完整 VBD 时要心里有数。

把三种「稳定」分开：时间积分、下降验收、demo 观察

精确求解的 backward Euler 在线性测试方程上 A-stable；这是时间积分结论。对 block 优化，$\Delta G=\Delta G_i$ 只是恒等式，只有精确 block minimizer 或经 backtracking/Armijo 接受的步才给出 $G$ 单调不增；这是优化接受结论。TinyVBD C++ 则是无 PSD、det guard、line search 的 QR raw full step，给定 demo 在低迭代下常表现为偏软而未爆，只是工程观察。三者不能互相替代，也不能据此保证任意参数下既不发散又收敛到精确隐式解。

后续：AVBD 补上硬约束与高刚度比

上面的局限不是终点。VBD 作者团队在一年后给出了直接的回应——AVBD（Augmented Vertex Block Descent），SIGGRAPH 2025。它在 VBD 的 block coordinate descent 骨架上，引入增广拉格朗日（augmented Lagrangian）的处理来对付硬约束和高刚度比。

直觉上：纯惩罚法（软）和纯拉格朗日法（硬约束、但难解）各有所长，augmented Lagrangian 是二者的融合——既保留惩罚项带来的良态，又通过显式维护一个拉格朗日乘子把约束逼到真正满足。这恰好对症 VBD 那两处短板：高刚度比下惩罚法迈不开步，而 augmented Lagrangian 能把「极硬」当作约束来精确满足，而不是当作一个越来越陡、越来越难下降的能量碗去硬啃。如果你想继续往下走，AVBD 是 VBD 之后最自然的下一站（见 参考文献）。

合上这本书

到这里，你已经把 TinyVBD 从头到尾走通了一遍。回头看这条坡道：你先补回了那块发虚的拼图——一步隐式欧拉 = 最小化增量势能 $G$（1.2）；然后用这把统一的尺子，把 PBD、XPBD、Projective Dynamics 摆进同一张谱系图（Part 2）；接着理解了 VBD 的精髓——一次只动一个顶点时有 $\Delta G=\Delta G_i$，所以经精确 block 最小化或下降验收的局部下降会成为全局下降（Part 3）；再把这套思想及 TinyVBD raw 实现的边界在 ~400 行代码里逐行对上号（Part 4）；最后亲手跑了高质量比、高刚度比、弯曲这些招牌实验，摸清了它的脾气和边界（Part 5）。

更重要的是，你现在拥有的不只是「VBD 怎么写」，而是一套能读懂整个 position/optimization-based 仿真家族的视角。下次再遇到一个新方法，你会本能地问：它在最小化什么？它是 primal 还是 dual？它的更新是 Gauss-Seidel 还是 Jacobi？它保留了多少 Hessian？——这几个问题，足以让你迅速把任何新方法放回谱系里。
